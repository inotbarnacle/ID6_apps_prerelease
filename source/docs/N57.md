# N57 and PowerDeck candidate

This branch extends iDriveDeck's native NBT Evo menus with an explicitly pinned
N57 DDE profile and the new PowerDeck app. BoostDeck retains upstream's single
page, circular/bar gauges, independent units, warning thresholds and OPTIONS
controls. No multi-panel navigation or BaseDiagnostik app is included.

## Profile and data

The shared file `/var/opt/hmi/data/ID5/n57-sgbd.txt` selects one six-digit DDE
SGBD index followed by a newline. Create it only after independently verifying
the actual ECU identity. The example `0F1F70` is one observed variant, not a
universal N57 identifier. Workers compare DDE identification with the pin;
missing, mismatched, malformed, unavailable or stale data is never fabricated.
Without a pin, upstream gasoline and generic diesel diagnostics remain usable.
PowerDeck requires a valid pin.

In BoostDeck choose **OPTIONS → BoostDeck settings → Engine profile → Diesel**.
Select **Configure gauges** to assign available N57 channels. The profile includes
RPM, fractional speed, boost, coolant/oil/intake/outside temperatures, rail
pressure, air flow, module voltage, fuel volume, DDE torque, calculated power,
DPF soot/pressure/regeneration distance, EGT, AdBlue and experimental relative
DDE torque (`464C`). Hide emissions gauges for a configuration that lacks SCR
or DPF hardware; stock N57 support remains available when they are shown.
Unsupported generic load/oil-pressure/timing fields stay hidden for pinned N57.
The relative-torque percentage is distinct from SAE calculated engine load.

**OPTIONS → BoostDeck settings → Diesel rail display scale** selects a rail
range of 1000, 1600, 2000 (default) or 2500 bar. Bars and circular dials use the
selected range in Diesel; the numeric DDE reading and gasoline scale are
unchanged. Labels follow the chosen pressure unit. The range is a display
preference, not an ECU limit or pressure target, and is stored independently in
`/var/opt/hmi/data/ID5/BoostDeck.rail-scale`.
The SI pressure choice uses kPa for boost/MAP and MPa for diesel rail (for
example, 1800 bar becomes 180.0 MPa).

The DDE values use a bounded `2C 03` / `2C 01` / `22 F303` transaction. It changes
only the temporary diagnostic slot F303; it does not flash or code the ECU.
The slot is cleared and defined under one diagnostic lease, with exact reply
widths and sample-age checks. A failed HSFZ connection can fall back to MOST,
including when NBT-AAD is installed. Transmission temperature remains
HSFZ-only on the current MOST diagnostic route. HUD Gauges remains retired from
this candidate; CarPlay/AAD navigation projection keeps its existing ownership.

Boost is absolute pressure (`4841`) minus barometric pressure (`4CF0`), both
decoded as hPa. Negative relative pressure is retained. A plausible value does
not independently calibrate these sources. DDE torque (`48A5`) is an ECU model
value; engine tuning can change its accuracy.

## PowerDeck

PowerDeck uses connector `121` and its own telemetry port. It displays RPM,
DDE-reported Nm and calculated kW/metric PS. Power is `Nm × RPM / 9549.2966`;
`PS = kW / 0.73549875`. This is not a wheel-power or dynamometer measurement.

Use **OPTIONS → Start measurement** to clear the recording buffer and record
the next fresh coherent RPM/torque/power samples. There is no pedal, speed or
RPM trigger. **Stop and save** stores up to 600 samples in
`/var/opt/hmi/data/ID5/PowerDeck.last.csv`. The previous saved measurement is
replaced only after a successful atomic save. Explicit recording can continue
through OPTIONS or a visible preview. Exiting through MENU saves and stops it.

**Live graph** shows the last 20 seconds. **Saved measurement** stops diagnostics
and draws Nm and kW/PS against RPM for the continuous rising-RPM segment with
the widest span. It does not join separate pulls or extrapolate across missing
samples. Curve labels identify the drawn peaks; the footer reports the raw
recorded peaks and their RPM. Review leaves the CSV unchanged.

PowerDeck uses the wide 8:3 RHMI geometry for 1280×480, 1440×540 and 1920×720.
The installer rejects it on compact 800×480 and 960×480 panels because its
runtime graph coordinates cannot use XML-only compact scaling. Other apps
retain upstream compact layout support. Physical acceptance still needs to be
performed on each target firmware/display; IDEmu uses synthetic ECU data.

## Build and package

Run the host suite from `source/native` and regenerate resources before building:

```sh
make -C source/native assets test
python3 source/tools/make_n57_dashboards.py
sh source/native/build.sh
python3 source/tools/test_package_n57.py
python3 source/tools/package_n57.py --output /path/to/output \
  --binaries source/native/out --build-info /path/to/BUILD-INFO.json
```

The build report must name the committed source/native tree and the SHA-256 of
each newly compiled library/worker, with `car_access=false`. Packaging validates
ELF architecture, manifests, image references, connector IDs, checksums and
executable modes. It refuses dirty source, mixed build identities and active
VIN/gateway/N57 configuration files. The bundle contains BoostDeck, ShiftDeck,
LaunchDeck, Engine Fault Codes and PowerDeck, with existing xDrive Control as
an optional component; it does not grant xDrive write authority.

xDrive remains HSFZ-only in this source change. Pinned N57 mode changes retain
the owner-VIN and verified DSC/LMV/EGS/DDE checks, read RPM/speed together, and
require the complete Park/drive snapshot to be no older than 750 ms before
sending the command. A slow or failed check sends no mode change.

To build the desktop installer with this candidate, overlay the checked bundle
while staging its usual upstream menus:

```sh
python3 source/tools/desktop-installer/stage-payload.py . \
  source/native/out/gaugedeck-fileops --candidate /path/to/candidate.zip
```

PowerDeck appears as an optional N57 app in the installer. Selecting it does not
create an ECU pin. Installation preserves existing profile settings and CSVs.

## Future installation and rollback

Installation is a separately authorized operation on a parked vehicle with
stable power. Follow [AgentReadMe](../../AgentReadMe.md) and verify the actual
firmware, both framework hashes, active display and plugin connector inventory.
Keep complete previous app folders and their permissions outside `Plugins`,
including `BoostDeck.signals`, `BoostDeck.prefs`, ShiftDeck settings and
`PowerDeck.last.csv`. Older fork B4 multi-panel assignments are migrated to
the chosen default page of the new single-panel profile; retain the original
file in the backup if returning to the fork.

Preserve `BoostDeck.rail-scale` with the other settings. A new instance starts
with the 2000-bar Diesel scale; a missing or malformed file leaves its current
choice intact. Its independent format does not rewrite existing gauge
assignments or unit preferences.

Stage full folders outside `Plugins`, compare every uploaded file by readback,
then replace only the selected apps. Restart iDrive while parked after the
copy is verified. First check idle RPM against the cluster, stationary speed,
freshness, engine/emissions settings, saved CSV review and worker stop after
MENU. Keep drivetrain writes, fault clearing and HUD rendering as separate
authorized tests. Restore the previous folders and settings, then perform a
parked restart if rollback is needed.

No installation or vehicle access is performed by the local build/package tools.
